# Workforce completion workflows

## Routes and placement

- Compensation → Monthly payroll/payslips (`/workforce/payroll`). HR/Admin prepare a statement per employee/month, submit, obtain independent review, then publish. Employees and permitted managers only see published/voided statements. Source revisions and void/reissue are auditable.
- Requests → Overtime/hourly leave (`/workforce/time`). Morning/afternoon presets derive from the company schedule. Lunch is excluded. Pending hourly and whole-day leave share reservation checks; approval/refund use the existing balance ledger. Manager authority is checked against current reporting scope.
- Dashboard and notification panel → Calendar/deadlines (`/workforce/calendar`). One on-demand query per selected month/scope, cached using normal data dependencies. Contract/probation/onboarding/training/offboarding/document/certificate/interview items link to the exact record when available. Read/dismiss preferences are per account/device, capped at 200 keys, and include date/version identity. There is no timer or Firestore polling.
- Profiles/employee list → Protected documents (`/workforce/documents`). Owners can manage qualifications, identity and other documents; HR/Admin can manage subordinate employment documents. Managers cannot download subordinate document files. Versions, expiry, archive and download audit are retained. Approved employment-certificate requests have a printable confirmation letter; it is not a digital signature.
- Employees → Transfers/promotions (`/workforce/changes`). Draft, submit, independent approval, then explicit apply on/after effective date. There is no unattended job that changes employees overnight. Current reporting hierarchy and proposal source fields are rechecked. Optional published salary and active contract references are validated. Pending approvals use the updated employee hierarchy; old managers lose access when scope changes.
- Employees → Import (`/workforce/imports`). CSV and XLSX, up to 20 rows and 256 KB. Map columns, validate duplicate codes/emails and authority, inspect create/update changes, confirm and download results. Preview is non-mutating; commit revalidates a source fingerprint and runs transactionally with idempotency. Blank update cells preserve old fields/background. New employee records do not create login accounts or assign roles.
- Shared workspace → News/policies (`/workforce/announcements`). Draft/schedule/publish, department audiences, pin, archive and version-specific acknowledgement. Editing published content returns it to draft and requires acknowledgement of the next version after publication. HR/Admin see completion reports.

## Payroll calculation boundary

This is an internal reviewed payroll workflow, not a statutory tax engine or bank transfer integration. Effective salary and monthly allowances are prorated over scheduled employment days, including mid-month salary changes. Approved overtime is counted only where it overlaps actual attendance. Tax, insurance, unpaid-time deductions and other adjustments are explicit reviewed line items. Missing attendance is flagged, not automatically deducted. Open months and pending time/leave requests prevent finalization. A reviewer must differ from the last preparer, and cannot process their own payroll. A sole Admin therefore needs another authorized Admin for their own statement; the workflow does not bypass self-approval protection.

Approved/published source snapshots are immutable. Attendance/leave changes into a locked month require voiding the statement first. Later salary/settings changes never rewrite published amounts. Void/reissue retains previous source/net values and history.

## Private document storage

Firestore stores metadata only. File bytes never appear in list responses or Firestore documents. Allowed uploads: PDF, PNG, JPEG; strict MIME signature, base64 and 512 KB limit; maximum 10 versions. Downloads are authenticated POST requests with current-scope validation and an audit event. The API streams an attachment with no-store headers, not a public URL. Files should still be scanned with the deployment's malware scanning service before accepting untrusted external uploads at scale.

Development defaults to `backend/.private/personnel/<organization>` (directory 0700, files 0600), excluded from Git. Keep that directory with backend backups. This works with cloud Firestore on the same development machine; files are not automatically synced to another server. For production set `HR_DOCUMENT_BUCKET` to an existing private Google Cloud Storage bucket and grant the backend service identity only object read/create permissions. No bucket is provisioned automatically. Production refuses local fallback. Optional `HR_DOCUMENT_DIR` changes the development root.

Objects use immutable SHA-256 keys, create-only writes and digest checks on download. A failed metadata transaction can leave an unreferenced object. Reconcile objects against all document-version keys during controlled maintenance, retain a grace period (at least 24 hours), review before deletion, and never delete an object referenced by an old version. Archiving intentionally preserves all versions. Do not run a collection-wide reconciliation on ordinary page loads.

## Storage and read policy

New collections: payrollStatements, timeRequests, personnelChanges, personnelDocuments, announcements, announcementReceipts, employeeImports under the existing organization. Existing Firestore deny-by-default client rules remain unchanged; access runs through the authenticated API. Commands use optimistic versions, idempotency receipts and scoped transactional reads. Read plans use employee IDs and bounded repository capacities, with cached reference data. Calendar retrieval is on demand; it currently loads bounded records for the authorized employee set and filters the requested date range in the service (not a scheduled notification service). Large organizations should add date indexes/server pagination before increasing repository caps.

`npm test --workspace @hoosoo/backend` includes service, HTTP authorization, replay, import, private storage and existing regression suites. Browser QA uses separate in-memory API fixtures; this is not evidence of cloud verification. Consult the delivery report for live checks performed.
